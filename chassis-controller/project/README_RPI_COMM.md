# 树莓派通信状态

当前版本已经主动断开全部树莓派任务通信。

## 当前 UART2 行为

- UART2 仍初始化为 `115200 baud`，TX=`B15`，RX=`B16`。
- Task10 保留电脑端 PID 调参所需的 ASCII 命令和 CSV 状态输出。
- Task1～Task9 不发送旧树莓派二进制状态包。
- 非 Task10 状态下收到的 UART2 字节只会从 FIFO 中清除，不解析任务命令。
- 旧 Task7 的 `[55 AA 01 01]` 放行协议、等待计时器和等待状态已经删除。
- Task4～Task7 当前都是不可发车的 H 题待实现占位。

## Task3 当前边界

Task3 已具备本地比赛状态机、5 ms 计时、底盘静止保护、B4 舵机安全输出和
OLED 页面，但目前没有位置数据源。按键启动后会显示 `WAIT SENSOR`，舵机保持
安全中位，不会用固定延时猜测钢球是否到达 `+5 cm` 或 `-5 cm`。

未来重新接入树莓派时，应遵守以下边界：

1. 树莓派只负责摄像头检测，并输出钢球位置、置信度、序号和采集时间戳。
2. UART 中断只收集并发布完整数据帧，不能在中断中运行浮点控制。
3. 5 ms 任务取得完整帧后，调用 `task3_ball_submit_measurement()`。
4. Task3 状态机和滚球控制器不需要因通信方式改变而重写。

旧通信协议仍可从 Git 历史中查看，不再保留在当前运行代码中。
