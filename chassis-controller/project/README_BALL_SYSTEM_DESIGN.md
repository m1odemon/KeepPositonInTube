# 车载一维平衡滚球整体方案

本文对应 2026 年江苏赛区 TI 杯 H 题，作为机械、树莓派视觉、MSPM0 控制、舵机执行和后续联调的统一设计基线。当前 `ball_control`、`ball_actuator` 和 Task3 本地状态机已加入 Keil；UART2 树莓派接收仍按阶段要求断开。

## 1. 最终职责划分

```text
车载控制摄像头（固定在车架正上方）
        |
        v
树莓派：识别钢球中心、管槽轴线、position_mm、confidence、采集时间戳
        |
        | UART V1：只发送视觉测量
        v
MSPM0：校验帧、状态估计、位置—速度串级控制、故障保护
        |
        | 目标水管角度
        v
角度—脉宽标定层：机构换算、硬限幅、变化率限制
        |
        v
B4 舵机内部位置环 -> 连杆 -> 水管倾角 -> 钢球运动

独立图传摄像头/发送模块 -> 场外电脑：实时显示、完整录像、回放
```

采用该分工的原因：

- 树莓派最了解图像采集时刻，适合输出经过几何标定的原始测量；
- MSPM0 调度确定、距离舵机最近，适合集中处理控制、安全和失联回中；
- UART 中保留原始位置，便于双方独立记录日志和定位问题；
- 树莓派重启或视觉程序卡死时，MSPM0 仍能在本地切回安全中位；
- 将 PID 固定在 MSPM0 后，图像算法升级不改变控制参数的物理含义。

第一版不让树莓派计算 PID，也不让它直接发送舵机 PWM。

## 2. 摄像头与坐标

控制摄像头和树莓派均安装在小车上。摄像头固定在车架正上方，不随水管倾斜；由于允许水管摆角很小，该结构可行，但摄像头支架必须足够刚，ROI 必须覆盖水管的全部允许姿态。

树莓派每帧应识别管槽两端或两个参考标记，将钢球中心投影到当前管槽轴线，再输出：

```text
O 点 = 0 mm
正方向一侧 > 0 mm
反方向一侧 < 0 mm
```

赛题水管名义长度为 250 mm、钢球直径约 10 mm。代码默认有效中心范围暂设为 `-120~+120 mm`，最终必须按挡板和真实可滚动范围重新标定。比赛第三项使用 `+50 mm` 和 `-50 mm`。

树莓派与 MSPM0 的 21 字节 V1 协议保持不变，详见 `README_BALL_RPI_TEAM.md`。

## 3. 推荐控制结构

### 3.1 位置外环

位置外环把位置误差转换成目标钢球速度：

```text
e_x = x_target - x

v_target = limit(
    Kp_pos * e_x + Ki_pos * integral(e_x),
    -v_limit,
    +v_limit
)
```

位置积分仅在误差进入积分区间后启用，并同时采用积分限幅和输出饱和条件抗饱和。第一轮调试必须令 `Ki_pos = 0`。

显式的 `v_target` 有两个作用：

- 限制大位置阶跃时的最大滚球速度，减少冲过目标点；
- 将“移动速度”和“最终位置精度”分开调节。

### 3.2 速度内环

摄像头位置经过时间戳差分和低通滤波得到 `v_ball`，速度内环输出目标水管角度：

```text
e_v = v_target - v_ball

angle_target =
    Kp_vel * e_v
    - Kd_vel * measured_ball_acceleration
    + angle_feedforward
```

微分项作用在测得的钢球加速度上，避免目标速度跳变造成微分冲击。摄像头差分噪声较大，因此第一轮调试必须令 `Kd_vel = 0`。

这一结构就是“位置—速度串级”。位置和速度都来自摄像头，所以不需要在水管上安装陀螺仪。两个环目前随新视觉帧一起更新，不应把速度环误认为一个独立的高速角度环。

### 3.3 车辆加速度前馈

小车启动或刹车时，钢球会受到车体纵向加速度引起的惯性扰动。后续可使用车体 IMU、编码器速度差分或规划加速度产生：

```text
angle_feedforward = Kff_accel * vehicle_acceleration
```

其符号必须通过“小车正向加速时钢球向哪侧滚动”的实车实验确认。未完成符号和量纲验证前，`Kff_accel` 必须保持 `0`。

## 4. 水管角度环是否必需

第一版不需要水管角度环。

普通舵机内部已经具有“目标舵机轴角度—实际舵机轴角度”的位置闭环。当前方案把 `angle_target` 通过机构标定换算为舵机脉宽，相当于使用：

```text
钢球位置环 -> 钢球速度环 -> 机构模型 -> 舵机内部位置环
```

以下问题出现时，再增加水管实际角度传感器：

- 舵机或连杆回差使相同脉宽对应不同水管角度；
- 负载变化后水管无法可靠到位；
- 车体振动使水管角度明显偏离命令；
- 已经正确调好位置—速度串级，仍无法达到 `±1 cm`。

若需要角度反馈，优先在水管转轴安装磁编码器或电位器，直接测量水管相对车体的角度。单独使用水管 IMU 会受到车体加速度和振动影响，并不是首选。

增加角度传感器后，结构扩展为：

```text
位置外环 -> 速度内环 -> 目标水管角度
                              |
                              v
                    水管角度闭环 -> 舵机脉宽
```

上层位置和速度控制无需重写。

## 5. 角度与舵机脉宽标定

`ball_actuator.c` 使用三点分段线性标定：

```text
水管负角度 -> pulse_at_min_angle_us
水管 0 度  -> pulse_neutral_us
水管正角度 -> pulse_at_max_angle_us
```

三点脉宽允许不对称，也允许正负方向反接。这样 PID 的输出单位始终是“度”，不再与舵机臂长度、连杆长度和 PWM 直接耦合。

实际装置必须测量：

- 水管真正水平时的中位脉宽；
- 安全正、负最大水管倾角及对应脉宽；
- 正水管角度是否确实使钢球向坐标正方向加速；
- 连杆是否存在碰撞、死区和明显回差。

当前默认 `±5°`、`1350/1500/1650 us` 只是安全的软件占位值，不是成品参数。

若机构模型表明角度—脉宽关系明显非线性，可在保持接口不变的情况下，把 `ball_actuator_map_angle_to_pulse_us()` 改为多点查表或模型求解。

## 6. 软件模块

| 模块 | 职责 |
|---|---|
| `ball_vision_link.c/.h` | ISR 字节收集、V1 帧解析、CRC 和完整快照发布 |
| `ball_control.c/.h` | 测量校验、位置/速度/加速度估计、位置—速度串级、状态机和超时故障 |
| `ball_actuator.c/.h` | 目标水管角度到舵机脉宽的标定、硬限幅和脉宽变化率限制 |
| `ball_balance_app.c/.h` | 组合以上模块，并把最终脉宽立即写到 B4 舵机 |
| `tests/ball_control_host_test.c` | 主机侧验证方向、速度限幅、积分限幅、视觉超时、硬限位和三点映射 |

控制模块只在取得新的有效视觉帧时更新 PID。5 ms 周期任务负责接收最新快照、检查视觉超时、推进舵机脉宽变化率限制并输出 PWM。

当前 Task3 已把 `ball_control` 和 `ball_actuator` 加入 Keil，并由
`task3_ball.c` 负责比赛动作状态机；树莓派通信、`ball_vision_link` 和
`ball_balance_app` 仍未接入。未来通信层只需在普通 5 ms 任务上下文把完整
测量交给 `task3_ball_submit_measurement()`。

原组合门面保持为未来参考边界：

```c
ball_control_config_t control_config;
ball_actuator_config_t actuator_config;
ball_balance_app_t ball_app;

ball_control_config_defaults(&control_config);
ball_actuator_config_defaults(&actuator_config);

/* 填入实车标定值后初始化。 */
ball_balance_app_init_with_config(&ball_app,
                                  &control_config,
                                  &actuator_config,
                                  now_us);

/* UART2 RX ISR：每个字节调用一次。 */
ball_balance_app_rx_uart_byte_from_isr(&ball_app, rx_byte, now_us);

/* 5 ms 定时任务：每次调用一次。 */
ball_balance_app_tick_5ms(&ball_app, now_us);
```

这些 `ball_balance_app` 调用目前仍未加入 `main` 或 ISR。

## 7. 与赛题任务对应的状态机

建议在控制器之外增加比赛任务状态机，滚球控制器只接收目标位置：

| 模式 | 小车任务 | 钢球目标 |
|---|---|---|
| SAFE | 未开始、故障或视觉失联 | 水管安全中位 |
| STATIC_TRANSFER | 小车静止 | `+50 mm` 稳定后切换为 `-50 mm` |
| DRIVE_TO_B | A 到 B | `0 mm` |
| DRIVE_ONE_LAP_CENTER | 绕行一圈 | `0 mm` |
| DRIVE_ONE_LAP_TARGET | 绕行一圈 | 现场指定位置 |

任务状态机不应绕过滚球控制器直接修改 PWM。

## 8. 推荐调试顺序

1. 不放钢球，只标定安全脉宽、中位和正负方向；
2. 水管固定水平，验证树莓派坐标的 `0 mm`、`+50 mm`、`-50 mm`；
3. 关闭 `Ki_pos`、`Kd_vel` 和加速度前馈；
4. 先调整速度环比例 `Kp_vel`，保证水管动作方向正确且不过激；
5. 再调整位置环比例 `Kp_pos` 和目标速度上限；
6. 完成静态中心保持，再完成 `+50 mm -> -50 mm`；
7. 仅在存在稳定静差时，加入很小的位置积分；
8. 小车低速直线行驶并保持中心；
9. 调整小车启动/刹车斜坡，必要时再启用车辆加速度前馈；
10. 最后测试整圈、指定位置和独立图传录像。

每一步都应记录 `position_mm`、`filtered_velocity_mm_s`、`target_velocity_mm_s`、`target_tube_angle_deg`、舵机脉宽、控制状态和故障码。

## 9. 当前结论

- 树莓派负责视觉测量，MSPM0 负责闭环和安全，是当前更稳健的职责划分；
- 位置—速度串级不需要水管陀螺仪；
- 水管角度是执行命令，不是第一阶段必须闭环的状态；
- 水管角度传感器属于达到静态稳定后再判断的增强项；
- 现阶段最重要的是机构角度—脉宽标定、视觉坐标稳定性和低增益静态联调。
