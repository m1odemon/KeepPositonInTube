# H题 Task3：静止滚球往返（树莓派断开阶段）

## 1. 赛题目标

小车静止，钢球从摆杆中心点 `O` 移动到 `+50 mm`，到达后折返到
`-50 mm` 并稳定。按键启动时开始计时，最终稳定后停止并冻结时间。

赛题指标为：

- 总时间不超过 `5 s`；
- `+50 mm` 和 `-50 mm` 的最大位置误差绝对值不超过 `10 mm`。

## 2. 当前已经完成

- Task3 菜单改为 `3:Ball +/-5cm`；
- Task3 启动时 `motor_enable=0`，左右轮函数另有强制归零保护；
- TIMA0 每 5 ms 推进 Task3 状态机和计时；
- B4 舵机初始化后保持安全中位；
- 已接入不包含通信的 `ball_control` 和 `ball_actuator`；
- OLED 显示阶段、时间、位置、目标、5 秒超时提示和通信状态；
- KEY4 会让 Task3 退出并让舵机回安全中位；
- 旧 Task3～7 树莓派发送包和 Task7 放行接收协议已删除。

## 3. 当前状态机

```text
READY
  -> KEY4
WAIT_SENSOR
  -> 获得第一份有效位置
TO_PLUS_50
  -> 控制器确认 +50 mm 已稳定
TO_MINUS_50
  -> 控制器确认 -50 mm 已稳定
DONE_HOLD
```

进入 `DONE_HOLD` 后停止计时，但控制器继续保持 `-50 mm`。视觉超时或位置
越过硬限位时进入 `FAULT` 并回安全中位。

## 4. 为什么现在停在 WAIT_SENSOR

赛题明确要求钢球位置检测采用摄像头。断开树莓派后，MSPM0 没有钢球位置，
无法可靠判断两个目标点，也无法保证 `±1 cm`。当前代码不会使用固定时间和
固定舵机角度盲目滚动，以免钢球撞击挡板或造成错误的“已完成”判断。

## 5. 未来接入点

通信适配层解析出完整位置帧后，应在普通 5 ms 任务上下文调用：

```c
task3_ball_submit_measurement(&measurement);
```

不要直接从 UART 中断调用该函数。树莓派接入只负责提供测量数据，不应直接
控制舵机 PWM，也不应重写 Task3 的比赛动作状态机。
